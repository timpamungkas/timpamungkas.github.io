Paradigma baru: spesifikasi lebih dulu (bukan vibe coding)

AI-native engineer, Spec-Driven Development, Spec-Kit, produk Xarent, dan MCP.

Masalahnya

Vibe coding cepat di hari pertama, mahal di bulan ketiga

Instruksi lepas

Prompt ditulis spontan, tidak disimpan, tidak bisa direview orang lain.

Asumsi tersembunyi

AI mengisi celah dengan tebakan. Tebakan itu masuk ke code tanpa ada yang tahu.

Hasil berubah-ubah

Prompt yang sama, jawaban berbeda. Tanpa acuan tertulis, tidak ada yang bisa dicek.

Software yang dipakai dan dirawat butuh acuan tertulis yang bisa direview: spec.

Jebakan berikutnya

Spec yang kabur tetap menghasilkan tebakan

Kabur

Pengunjung bisa booking mobil. Mobil tidak boleh double booking.

Kapan mobil kembali? Berapa harganya untuk 5,5 jam? Boleh langsung disewa lagi?

Presisi

  • Pick-up ≥ 2 jam dari sekarang
  • Sewa 1 jam sampai 30 hari
  • Durasi dibulatkan ke atas per jam
  • Jeda persiapan 1 jam antar sewa

Setiap aturan bisa diuji. AI tidak perlu menebak.

Model Context Protocol

MCP memberi AI konteks yang tidak ada di ingatannya

Context7

Dokumentasi terbaru Spring Boot 4, bukan kebiasaan Boot 3 dari data training AI.

Claude Code

+ Spec-Kit

Figma MCP

Layout, warna, font, dan aset langsung dari file desain Xarent.

MCP adalah standar terbuka untuk menghubungkan AI agent ke tools dan sumber data luar. Agent yang sama bisa membaca dokumentasi, desain, database, atau tiket tanpa integrasi khusus.

Sebelum live demo

AI itu non-deterministic

Prompt sama, hasil beda

Pertanyaan clarify, struktur code, dan nama file bisa berbeda dari rehearsal, bahkan dari satu run ke run berikutnya.

Yang dipelajari prosesnya

Fokus pada alur spec, plan, tasks, code, dan review. Outputnya tidak akan persis sama.

Justru karena hasilnya bisa berubah, spec dan review menjadi wajib.

Review itu wajib

Output AI bisa terlihat benar, padahal belum tentu

Terlihat

Plan dan code tampak masuk akal dan rapi.

Ternyata

Database, compiler, atau skenario uji bisa menolaknya.

Perbaikan

Perbarui dokumen desain dulu, lalu code-nya.

Review, review, review. Setiap output AI wajib direview sebelum lanjut ke langkah berikutnya.

Rangkuman

Empat hal untuk dibawa pulang

1. Spec dulu, code kemudian

Satu kebutuhan, satu spec yang detail. Spec di repo adalah sumber kebenaran.

2. Clarify sebelum plan

Keputusan dibuat manusia, bukan ditebak AI diam-diam.

3. MCP untuk konteks

Dokumentasi terbaru dan desain asli, bukan ingatan model.

4. Review setiap langkah

Skenario uji dari spec membuktikan hasilnya benar.

Di proyek nyata

Mulai kecil, mulai Senin depan
